# V3.1 项目章程 — Engineer Assist 智能运维平台

> **版本**: 3.1.0 | **日期**: 2026-05-30 | **状态**: 启动

---

## 1. 项目愿景

**让数据中心每个人都能做一线运维。**

V3.1 不是 AI 替代工程师，而是：
- 帮工程师**第一时间找到对的命令**
- 帮一线人员**正确执行简单操作**
- 让运维知识**可搜索、可复用、可审计**

## 2. 核心设计原则

| 原则 | 说明 |
|------|------|
| **Engineer Assist** | AI 是助手，推荐命令和参数，不替代决策 |
| **Audit Everything** | 每个操作有审计日志，可追溯、可回滚 |
| **Scale Ready** | 支持万台设备、千级并发、秒级响应 |
| **Type Safe** | 全栈 TypeScript + Python type hints，编译期发现错误 |
| **Fail Safe** | 高危操作必须确认，失败自动回滚，降级不崩溃 |

## 3. 技术栈

| 层 | 技术 | 理由 |
|----|------|------|
| **前端** | React 18 + TypeScript + Vite + Tailwind + Zustand + Recharts | 生态成熟，类型安全，暗色主题 |
| **后端** | FastAPI + SQLAlchemy 2.0 + Pydantic v2 + Dramatiq | 异步原生，自动 OpenAPI，任务队列 |
| **数据库** | PostgreSQL 16 + TimescaleDB + Redis 7 | 时序数据优化，缓存加速，JSONB 灵活 |
| **测试** | Vitest (前端) + pytest (后端) + Playwright (E2E) | 全栈覆盖 |
| **部署** | Docker Compose → K8s | 渐进式容器化 |

## 4. 里程碑

| 里程碑 | 周期 | 交付物 | 验收标准 |
|--------|------|--------|----------|
| **M1: 地基** | W1-4 | 数据库 + API + 前端骨架 | E2E: Chat→查询→展示 |
| **M2: 可视化** | W5-8 | 图表 + 告警增强 + 搜索 | E2E: Dashboard→告警→操作 |
| **M3: 命令助手** | W9-12 | 意图识别 + 命令推荐 + 操作追踪 | E2E: 自然语言→推荐→执行→结果 |
| **M4: 生产就绪** | W13-16 | 实时推送 + 审计 + 响应式 | E2E: 全流程 + 性能测试 |

## 5. 团队分工

| 角色 | 负责范围 | 交付标准 |
|------|----------|----------|
| **PM** (我) | 项目计划、任务分配、质量把控、文档 | 每阶段文档齐全 |
| **Database Engineer** | Schema 设计、迁移脚本、索引优化、种子数据 | 支持万台设备、千级并发 |
| **Backend Engineer** | API 端点、业务逻辑、中间件、测试 | OpenAPI 齐全、测试 >80% |
| **Frontend Engineer** | UI 组件、状态管理、交互设计、E2E 测试 | 骨架屏、实时更新、键盘导航 |

## 6. 质量门禁

每个阶段完成前必须通过：

```
✅ 后端: pytest 全部通过
✅ 前端: npm run test 全部通过
✅ E2E: Playwright 核心流程通过
✅ 文档: API 文档 + 组件文档 + 部署文档
✅ 代码审查: 无 TODO/FIXME/HACK，无未使用导入
✅ 类型检查: mypy + tsc 零错误
```

## 7. 约束条件

- 不允许硬编码数据（除测试 fixtures）
- 不允许空的 `__init__.py` 包含业务逻辑
- 不允许 `# type: ignore` 除非有注释说明
- 所有 API 端点必须有 OpenAPI 描述
- 所有 React 组件必须有 TypeScript props 接口
- 数据库查询必须有索引支持
