## 3. 配置体系详解

### 3.1 后端配置说明

系统配置通过 `pydantic-settings` 从环境变量加载，配置优先级：环境变量 > .env 文件 > 默认值。

#### 3.1.1 核心应用配置

```bash
# ===== 应用基础配置 =====
APP_NAME="Engineer Assist"              # 应用显示名称
APP_VERSION="3.1.0"                     # 版本号
DEBUG=false                             # 调试模式（生产环境必须设为 false）
API_V1_PREFIX="/api/v1"                # API 版本前缀

# ===== 当前环境标识 =====
# 可选值: development / staging / production
# 影响：日志级别、认证要求、CORS 策略
APP_ENV=production
```

#### 3.1.2 数据库配置

```bash
# ===== PostgreSQL 连接 =====
# 格式: postgresql+asyncpg://user:password@host:port/database
DATABASE_URL="postgresql+asyncpg://sre_app:${DB_PASSWORD}@postgres:5432/v31_sre"

# 连接池配置
DB_POOL_SIZE=20                         # 核心连接数（建议：CPU核心数 × 2-3）
DB_MAX_OVERFLOW=10                      # 额外最大连接数（峰值容忍）
DB_ECHO=false                           # SQL 日志输出（调试用，生产关闭）

# 连接超时
DB_POOL_TIMEOUT=30                      # 连接等待超时（秒）
DB_POOL_RECYCLE=1800                    # 连接回收时间（秒）
DB_POOL_PRE_PING=true                   # 使用前验证连接有效性
```

#### 3.1.3 Redis 配置

```bash
# ===== Redis 连接 =====
# 格式: redis://[password@]host:port/db
REDIS_URL="redis://redis:6379/0"

# Redis 连接池
REDIS_POOL_SIZE=10                      # 连接池大小
REDIS_SOCKET_TIMEOUT=5                  # Socket 超时（秒）
REDIS_SOCKET_CONNECT_TIMEOUT=3          # 连接超时（秒）
REDIS_RETRY_ON_TIMEOUT=true             # 超时重试
```

#### 3.1.4 JWT 认证配置

```bash
# ===== JWT 令牌 =====
# 生产环境必须设置！建议 64 字节随机字符串
# 生成命令: openssl rand -hex 64
JWT_SECRET_KEY="change-me-in-production-CHANGE-ME-NOW"

JWT_ALGORITHM="HS256"                   # 签名算法（推荐 RS256 生产环境）
JWT_ACCESS_EXPIRE_MINUTES=30            # Access Token 有效期（分钟）
JWT_REFRESH_EXPIRE_DAYS=7               # Refresh Token 有效期（天）
```

#### 3.1.5 CORS 配置

```bash
# ===== CORS 跨域 =====
# 生产环境严格限制为前端域名列表
# 格式: 逗号分隔的 origin URL 列表
CORS_ORIGINS="https://sre.example.com,https://admin.example.com"
```

#### 3.1.6 日志配置

```bash
# ===== 日志系统 =====
LOG_LEVEL="INFO"                        # DEBUG / INFO / WARNING / ERROR
LOG_FORMAT="json"                        # json（生产） / console（开发）
LOG_FILE="/var/log/sre-platform/app.log" # 日志文件路径（可选）
LOG_MAX_BYTES=104857600                 # 日志轮转大小（100MB）
LOG_BACKUP_COUNT=10                     # 保留日志文件数
```

#### 3.1.7 速率限制

```bash
# ===== 速率限制 =====
RATE_LIMIT_PER_MINUTE=60                # API 每分钟请求限制（每客户端）
RATE_LIMIT_CHAT_PER_MINUTE=20           # Chat 端点每分钟限制
RATE_LIMIT_BURST=100                    # 突发请求上限
```

### 3.2 前端配置

```bash
# frontend/.env
```

## 4. 开发环境部署

### 4.1 快速启动（一键部署）

```bash
# 1. 克隆项目
git clone <repository-url> v3.1
cd v3.1

# 2. 创建环境变量文件
cp .env.example .env
# 编辑 .env 文件设置必要的变量

# 3. 一键启动所有服务
docker compose up -d

# 4. 验证部署
curl http://localhost:8688/health        # 存活检查
curl http://localhost:8688/ready         # 就绪检查

# 5. 访问前端
# http://localhost:5173
```

### 4.2 手动启动（独立进程）

```bash
# 1. 启动基础设施
docker compose up -d postgres redis

# 2. 启动后端
cd backend
python -m venv .venv
source .venv/Scripts/activate  # Windows
# source .venv/bin/activate    # Linux/Mac
pip install -r requirements.txt

# 数据库迁移
alembic upgrade head

# 填充种子数据
python scripts/seed.py

# 启动 FastAPI 开发服务器
uvicorn app.main:app --reload --host 0.0.0.0 --port 8688

# 3. 启动前端（新终端）
cd frontend
npm install
npm run dev

# 4. 访问
# http://localhost:5173
```

## 5. 生产环境部署

### 5.1 前置准备

```bash
# 1. 生成生产密钥
openssl rand -hex 64 > secrets/jwt_secret.txt
openssl rand -base64 32 > secrets/db_password.txt

# 2. 准备 SSL 证书
# 使用 Let's Encrypt:
certbot certonly --standalone -d sre.example.com
cp /etc/letsencrypt/live/sre.example.com/fullchain.pem ssl/
cp /etc/letsencrypt/live/sre.example.com/privkey.pem ssl/

# 3. 配置 PostgreSQL 优化参数
cat > db/postgresql.conf << 'CONF'
shared_buffers = 4GB
effective_cache_size = 12GB
work_mem = 64MB
maintenance_work_mem = 1GB
max_connections = 100
wal_buffers = 64MB
random_page_cost = 1.1
effective_io_concurrency = 200
max_parallel_workers_per_gather = 4
max_parallel_workers = 8
autovacuum_max_workers = 4
autovacuum_naptime = 30s
shared_preload_libraries = 'pg_stat_statements'
CONF

# 4. 配置 Redis 优化参数
cat > redis/redis.conf << 'CONF'
maxmemory 384mb
maxmemory-policy allkeys-lru
save 900 1
save 300 10
save 60 10000
appendonly yes
appendfsync everysec
CONF
```

### 5.2 部署步骤

```bash
# 1. 构建生产镜像
docker compose -f docker-compose.prod.yml build

# 2. 启动服务
docker compose -f docker-compose.prod.yml up -d

# 3. 执行数据库迁移
docker compose -f docker-compose.prod.yml exec backend alembic upgrade head

# 4. 验证部署
curl -k https://sre.example.com/health
curl -k https://sre.example.com/ready

# 5. 查看日志
docker compose -f docker-compose.prod.yml logs -f --tail=100 backend
```

### 5.3 反向代理配置 (Nginx)

```nginx
# nginx/nginx.conf
upstream backend {
    server backend:8688;
    server backend:8688;
    keepalive 32;
}

server {
    listen 443 ssl http2;
    server_name sre.example.com;

    ssl_certificate /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    # 前端静态文件
    location / {
        root /usr/share/nginx/html;
        try_files $uri $uri/ /index.html;
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # API 反向代理
    location /api/ {
        proxy_pass http://backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
        proxy_connect_timeout 10s;
    }

    # WebSocket 代理
    location /ws {
        proxy_pass http://backend;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 3600s;
    }

    # 健康检查
    location /health {
        proxy_pass http://backend;
        access_log off;
    }
}

# HTTP 重定向到 HTTPS
server {
    listen 80;
    server_name sre.example.com;
    return 301 https://$server_name$request_uri;
}
```

```yaml
            port: 8688
          initialDelaySeconds: 30
          periodSeconds: 30
          timeoutSeconds: 5
```

### 9.1 PostgreSQL 备份

## 10. 故障排查指南

### 10.1 常见问题速查表

| 症状 | 可能原因 | 诊断命令 | 解决方案 |
|------|---------|---------|---------|
| 服务无法启动 | 端口冲突 | `netstat -ano \| findstr :8688` | 停止占用进程或更换端口 |
| 数据库连接失败 | 密码错误/服务未启动 | `docker compose logs postgres` | 验证 POSTGRES_PASSWORD / 重启服务 |
| Redis 连接超时 | Redis 未就绪 | `redis-cli -h localhost ping` | 检查 Redis 服务状态 |
| JWT 认证失败 | 密钥不匹配 | `docker compose logs backend \| grep JWT` | 统一密钥配置 |
| 前端白屏 | API 代理配置错误 | 浏览器 F12 → Network 标签 | 检查 VITE_API_BASE_URL |
| 聊天无响应 | ChatService 异常 | `curl localhost:8688/api/v1/chat` | 检查后端日志 |
| 仪表盘无数据 | 数据库空 | `docker compose exec postgres psql -c "SELECT count(*) FROM assets"` | 运行 seed 脚本 |
| CORS 错误 | Origin 未配置 | 浏览器 F12 → Console | 添加前端域名到 CORS_ORIGINS |

### 10.2 日志分析命令

## 11. 安全加固清单

### 11.1 部署前安全检查

- [ ] `DEBUG=false` — 生产环境关闭调试模式
- [ ] `JWT_SECRET_KEY` — 设置为 64 字节随机密钥，不为空
- [ ] `CORS_ORIGINS` — 严格限制为已知前端域名
- [ ] 数据库密码 — 使用 32 字符以上随机密码，通过 Secret 注入
- [ ] TLS/SSL — 启用 HTTPS，配置证书自动续期
- [ ] 速率限制 — 配置 API 速率限制（60 req/min/client）
- [ ] 日志级别 — 生产环境设置为 INFO 或 WARNING
- [ ] `DB_ECHO=false` — 生产环境关闭 SQL 日志输出
- [ ] 敏感信息 — 确认 .env / secrets 目录不在 git 追踪中
- [ ] 审计日志 — 确认 audit middleware 已启用
- [ ] 操作系统 — 容器使用非 root 用户运行

### 11.2 持续安全建议

1. **依赖更新**：每月更新依赖版本，关注安全公告
2. **密钥轮换**：JWT 密钥每 90 天轮换一次
3. **访问审计**：定期审查审计日志，识别异常模式
4. **渗透测试**：每季度进行安全测试
5. **补丁管理**：基础镜像（Python/Node/PostgreSQL/Redis）每月更新
6. **网络隔离**：数据库和 Redis 只暴露在内部网络
